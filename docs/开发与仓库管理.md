# 开发与仓库管理

## 环境

- 微信开发者工具：导入仓库的 `miniprogram/`，AppID 已在项目配置中。
- Node.js 22 或更高版本：源码检查、测试与人机基准。
- Python 3：官方编译检查与 ZIP 打包，无额外 Python 依赖。
- 小程序运行不需要 npm 构建、云开发或业务服务器；首次获取代码仍可能需要互联网。

## 常用命令

以下命令均在仓库根目录运行。核心检查与测试不需要安装 npm 依赖。

```sh
npm run check
npm test
npm run test:network
npm run compile:wechat
npm run package:wechat
```

`npm test` 运行规则、策略、页面、布局及协议单元测试。
`npm run test:network` 单独串行运行全部真实 UDP 会话文件，约需数分钟；各文件共用端口，不能同时手工启动多组。
GitHub Actions 在 Linux 和 Windows 上运行源码检查与单元测试；不运行依赖桌面开发者工具的官方编译或真实 UDP 会话。

官方编译需要 Windows 上已安装微信开发者工具；安装路径不同可在 PowerShell 中设置：

```powershell
$env:WXTOOLS = '你的微信开发者工具安装目录'
npm run compile:wechat
```

打包版本默认读取 `package.json`，也可手动指定：

```sh
python tools/package_wechat.py 1.6.10
```

ZIP 仅包含小程序运行文件和说明文档，排除开发者工具私有配置。打包不会上传体验版或修改 GitHub。

## 可选桌面验证

需要微信自动化／浏览器截图时，再安装独立的本地工具依赖：

```sh
npm ci --prefix tools/runtime
node tools/preview_wechat.js
```

自动化需事先开启微信开发者工具的本机 `9421` 自动化端口。
`screenshot_mini_preview.js` 默认使用本机 Windows Edge；它生成静态布局验证，不是真机截图。
Node UDP 测试也不能代替 Android/iPhone 在 Wi-Fi、热点、锁屏和断线恢复上的实际验证。

## 目录与保留边界

- `miniprogram/`：运行源码、页面和运行资源。
- `tests/`：回归测试与实体牌局面夹具。
- `tools/`：检查、编译、打包、基准、复盘和可选桌面工具。
- `tools/fixtures/`：旧版人机策略快照，供对照测试使用，不能改成当前策略。
- `assets/`：头像源素材；运行版头像位于 `miniprogram/assets/`。
- `docs/`：玩法、维护说明及精选验证摘要。
- `dist/`、`output/`：本机生成物，不入库；包括交付 ZIP、详细牌局、浏览器用户目录和截图。
- `project.private.config.json`、依赖目录、环境变量文件和私钥不入库。

`review_guandan_analysis.js` 等历史复盘工具需要先生成 `dist/validation/` 中的大型分析记录；这些数据不随仓库提交。
历史复盘需要使用 `tools/fixtures/` 中对应的冻结策略生成输入，不能直接用当前策略冒充旧版；具体输入文件名见各工具读取的 `dist/validation/` 路径。
普通开发只需要检查和测试，历史复盘不是启动前置步骤。

## 后续 Git 流程

```sh
git pull --ff-only
git switch -c feature/你的功能名
# 完成修改与检查
git add <本次相关文件>
git commit -m "说明具体改动"
git push -u origin HEAD
```

通过 GitHub Pull Request 审阅后合并到 `main`。升级本地交付版本时，同步维护 `package.json`、`CHANGELOG.md` 和开发经验中的版本记录。
版本标签只对应代码快照，体验版上传、审核与正式发布单独记录。
